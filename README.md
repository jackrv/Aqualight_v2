# AquaLight — ESP8266 D1 mini

Контроллер четырёх каналов аквариумного светильника с редактором суточного графика в Telegram Mini App. Прошивка работает на ESP8266; статический редактор — на GitHub Pages. Дополнительный сервер не требуется.

## Подключение

| Канал | Пин D1 mini | GPIO |
|---|---|---|
| ch0 / белый | D1 | 5 |
| ch1 / красный | D2 | 4 |
| ch2 / зелёный | D5 | 14 |
| ch3 / синий | D6 | 12 |

ШИМ: 0–255, 1 кГц, активный высокий уровень. Подключайте выходы к управляющим входам соответствующих драйверов/MOSFET, с общей землёй. Светодиодную нагрузку питает её блок питания, а не GPIO платы.

## Первый запуск

1. Скопируйте `include/secrets.example.h` в `include/secrets.h` и заполните Wi-Fi, токен бота, собственный числовой Telegram ID (`JACKRV_ID`) и HTTPS URL редактора (`WEBAPP_URL`). Если `include/secrets.h` уже настроен, сохраните его. Секреты исключены из Git и в репозитории отсутствуют.
2. Разместите **все три файла** каталога `web/` в корне репозитория GitHub Pages. В Settings → Pages выберите публикацию нужной ветки и корневого каталога. URL страницы должен совпадать с `WEBAPP_URL`. В этом проекте файлы подготовлены локально; публикация в GitHub не выполнялась.
3. В BotFather при необходимости разрешите домен Mini App командой `/setdomain`. Настраивать Menu Button не нужно: редактор открывается кнопкой клавиатуры, которую отправляет прошивка.
4. Подключите D1 mini и выполните в терминале PlatformIO:

   ```sh
   pio run -e d1_mini
   pio run -e d1_mini -t upload
   # Только при первом запуске: создаёт файловую систему с выключенным светом.
   pio run -e d1_mini -t uploadfs
   pio device monitor -b 115200
   ```

   `uploadfs` перезаписывает файловую систему и сохранённый график. При обычном обновлении прошивки используйте только `upload`. При нескольких подключённых платах укажите нужный порт через `--upload-port`.
5. Дождитесь Wi-Fi и NTP, напишите боту `/start` в личном чате. Нажмите «💡 Редактор освещения» на обычной клавиатуре Telegram. После сохранения дождитесь подтверждения бота. В дальнейшем открывайте редактор через обновлённую кнопку; `/editor` создаёт её заново с текущим графиком.

До первого сохранения каналы выключены. При перезапуске выходы остаются выключенными до получения корректного времени. После синхронизации расписание работает и при потере интернета; после полного отключения питания требуется повторный NTP, поскольку у платы нет автономных часов.

## Управление

- `/start`, `/editor` — помощь и кнопка с текущим графиком.
- `/status` — местное время с EET/EEST, текущие значения ШИМ, состояние LittleFS и свободная RAM.
- `/schedule` — текущий JSON; его можно сохранить как резервную копию.
- Сообщение с JSON — загрузка графика вручную (также используется при открытии редактора в обычном браузере и копировании JSON).

Управление доступно только `JACKRV_ID` в личном чате. Поля `chat.id` и `from.id` проверяются для каждого сообщения, включая `web_app_data`.

В редакторе выберите канал, двигайте точки или задавайте время/яркость полями. Нажатие на пустое место графика добавляет точку. Крайние точки не удаляются и синхронизируют яркость между собой, чтобы на границе суток не было скачка. Если переданные через URL данные повреждены, сохранение заблокировано.

## Формат графика

```json
{
  "ch0": [{"t":0,"v":0},{"t":420,"v":0},{"t":540,"v":230},{"t":1140,"v":230},{"t":1260,"v":0},{"t":1440,"v":0}],
  "ch1": [{"t":0,"v":0},{"t":1440,"v":0}],
  "ch2": [{"t":0,"v":0},{"t":1440,"v":0}],
  "ch3": [{"t":0,"v":0},{"t":1440,"v":0}]
}
```

Ровно четыре канала, каждый содержит 2–12 точек. `t` — целое число минут 0–1440, строго возрастает; `v` — целая яркость 0–255. Первая точка — 0, последняя — 1440; их яркость должна совпадать. Максимальный размер JSON — 2048 байт. Неверный график не меняет действующий. Запись сначала идёт в `/schedule.tmp`, затем файл атомарно заменяет `/schedule.json`. Автоматического форматирования при ошибке монтирования нет.

Яркость рассчитывается линейно с учётом секунд, обычно каждые 250 мс. Синхронные сетевые запросы могут задерживать следующий пересчёт на время подключения/тайм-аута; аппаратный ШИМ продолжает выдавать последнее значение. Это не система жёсткого реального времени.

## Telegram и время

`Telegram.WebApp.sendData()` работает с **KeyboardButton.web_app в ReplyKeyboardMarkup**. Inline-кнопка и Menu Button имеют другой механизм возврата данных и не подходят для этой схемы без сервера. Прошивка отправляет сырой JSON Bot API, получает `message.web_app_data.data` через `getUpdates` и не зависит от отсутствующих полей библиотек Telegram. При подключении удаляется прежний webhook с сохранением очереди; другой экземпляр бота одновременно запускать не следует.

Документация: [Telegram Mini Apps](https://core.telegram.org/bots/webapps#keyboard-button-mini-apps), [KeyboardButton](https://core.telegram.org/bots/api#keyboardbutton), [web_app_data](https://core.telegram.org/bots/api#webappdata).

Часовой пояс: `EET-2EEST,M3.5.0/3,M10.5.0/4`, UTC+2 зимой и UTC+3 летом. Это строка `TZ_Europe_Kiev` из [ESP8266 Arduino Core 3.1.2](https://github.com/esp8266/Arduino/blob/3.1.2/cores/esp8266/TZ.h). Дополнительное ручное смещение к NTP не прибавляется. Если правила часового пояса изменятся, обновите `TIMEZONE` в `include/main.h`.

HTTPS проверяет имя сервера, срок действия и цепочку доверия. Публичные корневые сертификаты находятся в `include/telegram_ca.h`; текущая цепочка api.telegram.org проверена через OpenSSL. При смене Telegram удостоверяющего центра может потребоваться обновление корней.

## Проверки

```sh
pio run -e d1_mini
pio run -e d1_mini -t buildfs
c++ -std=c++11 -Iinclude -I.pio/libdeps/d1_mini/ArduinoJson/src tests/schedule_test.cpp -o /tmp/aquarium_schedule_test
/tmp/aquarium_schedule_test
node tests/web_test.js
node --check web/app.js
python3 tests/timezone_test.py
```

C++ тест использует тот же валидатор и интерполяцию, что и прошивка. Проверяются границы, неверные типы, порядок точек, максимальный график и линейный рост/спад. JS тест проверяет формат редактора и передачу через URL. Тест времени сравнивает POSIX TZ с Europe/Kyiv на зиме, лете и переходах DST.

Проверки на подключённом ESP8266 и в Telegram на телефоне требуют отдельного запуска: сохранение после отключения питания, фактические сигналы на четырёх выходах, доставка Mini App → бот и потребление RAM при TLS. Прошивка и редактор не загружались на устройство/хостинг автоматически.
