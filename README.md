# AquaLight — ESP8266 D1 mini

Контроллер четырёх каналов аквариумного светильника с редактором суточного графика в Telegram Mini App. Прошивка работает на ESP8266; статический редактор — на GitHub Pages. Дополнительный сервер не требуется.

## Подключение

| Канал | Пин D1 mini | GPIO |
|---|---|---|
| ch0 / белый | D1 | 5 |
| ch1 / красный | D7 | 13 |
| ch2 / зелёный | D5 | 14 |
| ch3 / синий | D6 | 12 |
| Датчик воды DS18B20 (данные) | D2 | 4 |

ШИМ: 10 бит (0–1023), 1 кГц, активный высокий уровень. Подключайте выходы к управляющим входам соответствующих драйверов/MOSFET, с общей землёй. Светодиодную нагрузку питает её блок питания, а не GPIO платы.

Температура воды читается с DS18B20 раз в 10 секунд без блокировки основного цикла (библиотека GyverDS18) и выводится в `/status`. Если минуту нет ни одного верного чтения, `/status` показывает «Датчик воды не отвечает». На освещение температура не влияет.

## Первый запуск

1. Скопируйте `include/secrets.example.h` в `include/secrets.h` и заполните Wi-Fi, токен бота, собственный числовой Telegram ID (`TELEGRAM_OWNER_ID`) и HTTPS URL редактора (`WEBAPP_URL`). Если `include/secrets.h` уже настроен, сохраните его. Секреты исключены из Git и в репозитории отсутствуют.
2. Разместите **все четыре файла** каталога `web/` в корне репозитория GitHub Pages. В Settings → Pages выберите публикацию нужной ветки и корневого каталога. URL страницы должен совпадать с `WEBAPP_URL`. В этом проекте файлы подготовлены локально; публикация в GitHub не выполнялась.
3. В BotFather при необходимости разрешите домен Mini App командой `/setdomain`. Настраивать Menu Button не нужно: редактор открывается кнопкой клавиатуры, которую отправляет прошивка.
4. Подключите D1 mini и выполните в терминале PlatformIO:

   ```sh
   pio run -e d1_mini
   pio run -e d1_mini -t upload
   # Нужен только для чистой платы без файловой системы: создаёт LittleFS со стартовым графиком.
   pio run -e d1_mini -t uploadfs
   pio device monitor -b 115200
   ```

   `uploadfs` перезаписывает файловую систему и сохранённый график. При обычном обновлении прошивки используйте только `upload`. При нескольких подключённых платах укажите нужный порт через `--upload-port`.
5. Дождитесь Wi-Fi и NTP, напишите боту `/start` в личном чате. Нажмите «💡 Редактор освещения» на обычной клавиатуре Telegram. После сохранения дождитесь подтверждения бота. В дальнейшем открывайте редактор через обновлённую кнопку; `/editor` создаёт её заново с текущим графиком.

Стартовый график (пресет «Травник · 10 часов») встроен в прошивку: если на плате нет `/schedule.json` или файл повреждён, прошивка при запуске сама создаёт его и сообщает об этом в приветствии. Поэтому `uploadfs` не обязателен — достаточно, чтобы на плате уже была файловая система LittleFS, например от прежней прошивки. Если файловая система не монтируется, свет работает по встроенному графику, но сохранение графика и OTA недоступны, пока не выполнен `uploadfs`. Встроенный график лежит в `include/default_schedule.h` и должен совпадать с `data/schedule.json` — это проверяет тест. Выходы выключены, пока плата не знает время. После синхронизации расписание работает и при потере интернета. Время каждые 10 секунд сохраняется в RTC-памяти ESP8266, поэтому после OTA, watchdog, сбоя программы и кнопки Reset свет продолжает идти по графику сразу, не дожидаясь NTP (отставание до ~10 секунд исправляет первый ответ NTP; до него `/status` показывает «без NTP»). После полного отключения питания RTC-память пуста и требуется NTP: у платы нет автономных часов. Чтобы свет не зависел от интернета и после отключения питания, нужен модуль часов с батарейкой (DS3231).

## Управление

- `/start` — приветствие с текущим состоянием (свет, температура воды), список команд и кнопка редактора. Заодно настраивает меню команд рядом с полем ввода для этого чата; у владельца в нём есть `/update`.
- `/editor` — заново прислать кнопку редактора с текущим графиком.
- `/status` — компактная сводка: время, шкалы яркости каналов с направлением изменения, ближайшая точка графика, Wi-Fi, время работы и причина запуска, память, версия и сборка. После успешного ответа входящая команда удаляется из личного чата.
- `/schedule` — текущий JSON; его можно сохранить как резервную копию.
- `/update` — разрешить установку прошивки через Telegram на 5 минут.
- `/cancel` — отменить ожидание файла прошивки.
- Сообщение с JSON — загрузка графика вручную (также используется при открытии редактора в обычном браузере и копировании JSON).

На неизвестный текст бот отвечает одной строкой с подсказкой про `/start`. Управление доступно только `TELEGRAM_OWNER_ID` и аккаунтам из `TELEGRAM_EXTRA_USERS` в личном чате; остальным бот не отвечает, в том числе на `/start`. Поля `chat.id` и `from.id` проверяются для каждого сообщения, включая `web_app_data`.

В редакторе выберите канал, двигайте точки или задавайте время/яркость полями. Нажатие на пустое место графика добавляет точку. Крайние точки не удаляются и синхронизируют яркость между собой, чтобы на границе суток не было скачка. Если переданные через URL данные повреждены, сохранение заблокировано.

## Дополнительные пользователи

Бот отвечает только владельцу (`TELEGRAM_OWNER_ID`) и аккаунтам из необязательного списка `TELEGRAM_EXTRA_USERS` в `secrets.h` — до четырёх числовых Telegram ID через запятую. Сообщения остальных аккаунтов молча игнорируются; бот работает только в личных чатах.

| | Владелец | Дополнительный пользователь |
|---|---|---|
| `/status`, `/schedule`, редактор, сохранение графика | да | да |
| `/update`, отправка и установка прошивки | да | нет |
| Приветствие после загрузки, сообщения OTA | получает | не получает |

Каждый пользователь должен сам открыть чат бота и нажать `/start`: бот не может написать тому, кто с ним не начинал диалог. Когда график сохраняет один пользователь, остальным приходит сообщение с обновлённой кнопкой редактора — график передаётся в адресе кнопки, и старая кнопка открыла бы устаревшие данные. Список зашит в прошивку: чтобы добавить или убрать пользователя, измените `secrets.h` и обновите прошивку. Свой Telegram ID можно узнать у бота `@userinfobot`.

## Обновление прошивки через Telegram (OTA)

Первую прошивку с поддержкой OTA нужно один раз загрузить по USB: `pio run -e d1_mini -t upload`. После этого последующие версии этого проекта можно устанавливать через личный чат бота.

1. Соберите новую версию: `pio run -e d1_mini`, используя свои актуальные настройки `include/secrets.h`.
2. Сборка создаёт `.pio/build/d1_mini/firmware.bin` и рядом `firmware.bin.md5`. В последнем — готовая подпись вида `md5:0123456789abcdef0123456789abcdef`; та же строка выводится в терминале.
3. Напишите `/update` боту с аккаунта `TELEGRAM_OWNER_ID`.
4. В течение 5 минут отправьте **firmware.bin как документ**, вставив всю строку из `firmware.bin.md5` **в подпись к документу**, а не отдельным сообщением. Файл `.md5` отправлять не нужно. Отправка корректного документа запускает установку. Пока файл не отправлен, `/cancel` отменяет ожидание.
5. Дождитесь сообщения об успешной записи и перезагрузки, затем проверьте `/status`: там отображаются версия и дата сборки.

Бот проверяет владельца и личный чат, окно обновления, расширение, доступное место, точный размер HTTP-ответа, заголовок ESP8266, встроенную метку `AQUALIGHT:ESP8266:D1_MINI:OTA_V1` и MD5. Поэтому `littlefs.bin`, ESP32-образ, старые версии без метки и повреждённые файлы не подходят. Метка защищает от случайного выбора чужого образа; MD5 проверяет целостность и не является цифровой подписью.

Файл скачивается напрямую из Telegram по HTTPS с проверкой сертификата и записывается порциями в свободную область flash. В RAM целиком не хранится. Telegram получает подтверждение обработки сообщения до установки, чтобы после перезапуска не выдавать тот же документ повторно. Незавершённая загрузка или ошибка проверки не назначают новую прошивку для загрузки; устройство продолжает работать на прежней версии. При ошибке начните повторную попытку с `/update`.

Обновляется только программа (`U_FLASH`), LittleFS с графиком не перезаписывается. В новых версиях сохраняйте прежнюю разметку flash и поддержку OTA. Сборка содержит настройки Wi-Fi и токен из вашего `secrets.h`; файл прошивки предназначен для вашего устройства, а не для публичной публикации. Во время загрузки график продолжает пересчитываться между порциями данных; при перезагрузке свет отключается до повторной синхронизации времени.

Автоматического отката после запуска логически неисправной новой программы нет. Сбой питания во время копирования загрузчиком может потребовать восстановления по USB. См. [Updater и устройство OTA ESP8266](https://arduino-esp8266.readthedocs.io/en/3.1.2/ota_updates/readme.html) и [Telegram getFile](https://core.telegram.org/bots/api#getfile).

## Сборка и отправка из VS Code

В проекте есть задача **AquaLight: Собрать и отправить в Telegram** (`.vscode/tasks.json`). Для запуска нажмите **⌘⇧B на macOS** или **Ctrl+Shift+B на Windows/Linux**. Либо выберите Terminal → Run Task → AquaLight: Собрать и отправить в Telegram. Это задача сборки VS Code по умолчанию; обычная кнопка Build расширения PlatformIO по-прежнему только собирает проект.

Задача собирает `d1_mini`, проверяет образ и MD5, затем автоматически отправляет `firmware.bin` в личный чат `TELEGRAM_OWNER_ID` с ботом. В сообщении уже есть контрольная сумма и кнопка **«Установить прошивку»**. Нажмите её в Telegram: ESP8266 начнёт проверку, загрузку и установку. Предварительная команда `/update` в этом режиме не нужна. Подпись вручную копировать не требуется.

На ESP8266 сначала должна быть установлена версия с поддержкой этой кнопки — по USB либо предыдущим способом через `/update` и ручную отправку документа. Получатель должен ранее открыть бота командой `/start`. На компьютере нужны Python 3 и PlatformIO; дополнительных Python-библиотек и авторизации Telegram-аккаунта не требуется. Токен и Telegram ID берутся из локального `include/secrets.h` и не передаются в аргументах команд.

Почему нужна кнопка в Telegram: `sendDocument` отправляет сообщение **от бота пользователю**, а не входящий документ от пользователя боту. Контроллер получает отдельный `callback_query` после нажатия кнопки. Он проверяет пользователя, личный чат, автора сообщения и соответствие контрольной суммы кнопке. Скрипт на компьютере не вызывает `getUpdates` и не мешает опросу на плате. См. [sendDocument](https://core.telegram.org/bots/api#senddocument) и [CallbackQuery](https://core.telegram.org/bots/api#callbackquery).

Для сборки без отправки выберите задачу **AquaLight: Только сборка и проверка**. Из терминала доступны те же операции:

```sh
# Собрать и отправить в Telegram:
python3 scripts/send_firmware.py --build
# Собрать и проверить, без сетевой отправки:
python3 scripts/send_firmware.py --build --dry-run
# Отправить уже собранный файл:
python3 scripts/send_firmware.py
```

Если сборка или проверка завершатся ошибкой, файл не отправляется. Скрипт не повторяет отправку автоматически при сетевой ошибке, поскольку Telegram мог уже принять документ. Фактическая установка начинается только после нажатия кнопки владельцем в Telegram.

## Обновление редактора

Редактор публикуется на GitHub Pages из этого же репозитория: `git push` в `main` обновляет страницу. Скрипты подключены с меткой версии (`app.js?v=…`) — это хеш их содержимого, поэтому изменённый файл получает новый адрес и не берётся из кэша браузера. После правок в `web/*.js` обновите метку:

```sh
python3 scripts/stamp_web.py
```

`node tests/web_test.js` падает, если метка устарела. Сам `index.html` GitHub Pages разрешает кэшировать 10 минут, так что новая версия может появиться в Telegram с такой задержкой.

## Пресеты

В редакторе над каналами есть список пресетов. Выбор пресета загружает его в редактор; на контроллер он попадает только после «Сохранить в контроллер». Встроенные пресеты заданы в `web/presets.js`: «Травник · 10 часов» (совпадает с графиком, встроенным в прошивку), «Спокойный · 8 часов», «С дневной паузой», «Вечерний · 13–23», «Отпуск · 6 часов» и «Утро и синяя ночь» (свет уже горит к 07:00, ровный день, синее свечение до полуночи).

- `＋` сохраняет текущий график редактора как свой пресет с названием до 24 символов (до 12 своих пресетов).
- `★` делает выбранный пресет основным; он отмечен звёздочкой и открывается, когда редактор запущен без графика от контроллера. Изначально основной — «Травник · 10 часов».
- `🗑` удаляет свой пресет; встроенные удалить нельзя.

Свои пресеты и выбор основного хранятся в облачном хранилище Telegram (общие для всех ваших устройств), а если оно недоступно — в памяти браузера на этом устройстве. Контроллер пресеты не хранит: в нём всегда один действующий график.

## Формат графика

Редактор показывает яркость в процентах (ось графика и поле ввода); в JSON и в контроллере она по-прежнему хранится числом 0–255, где 255 — это 100%.

```json
{
  "ch0": [{"t":0,"v":0},{"t":420,"v":0},{"t":540,"v":230},{"t":1140,"v":230},{"t":1260,"v":0},{"t":1440,"v":0}],
  "ch1": [{"t":0,"v":0},{"t":1440,"v":0}],
  "ch2": [{"t":0,"v":0},{"t":1440,"v":0}],
  "ch3": [{"t":0,"v":0},{"t":1440,"v":0}]
}
```

Ровно четыре канала, каждый содержит 2–12 точек. `t` — целое число минут 0–1440, строго возрастает; `v` — целая яркость 0–255. Первая точка — 0, последняя — 1440; их яркость должна совпадать. Максимальный размер JSON — 2048 байт. Неверный график не меняет действующий. Запись сначала идёт в `/schedule.tmp`, затем файл атомарно заменяет `/schedule.json`. Автоматического форматирования при ошибке монтирования нет.

Яркость рассчитывается с учётом секунд каждые 250 мс по системному таймеру, а не в `loop()`: долгий запрос к Telegram или загрузка OTA пересчёт не останавливают. Это не система жёсткого реального времени.

Между точками графика яркость идёт не по прямой, а по гладкой кривой — монотонному кубическому сплайну (PCHIP). Кривая проходит ровно через каждую точку, не имеет углов и не выходит за пределы соседних значений. Точку на продолжающемся подъёме или спаде она проходит без остановки; выравнивается только там, где начинается плато или направление меняется. Одиночный переход между двумя плато получается S-образным, как у синусоиды. Сутки замкнуты, поэтому полночь — такая же гладкая точка, как остальные. Редактор рисует ту же кривую (`web/schedule.js`), поэтому картинка совпадает со светом.

Значения графика 0–255 — это воспринимаемая яркость. Между соседними значениями прошивка считает ещё 64 промежуточных шага и переводит результат в 10-битный ШИМ по гамма-кривой 2,2, поэтому рассвет и закат идут без заметных ступеней. Следствие: 128 в графике — это половина яркости на глаз, но около 22% скважности ШИМ; 255 по-прежнему даёт 100%. Любое значение выше нуля оставляет канал включённым. 10 бит — предел программного ШИМ ESP8266 на 1 кГц; для ещё более плавного нижнего края нужен внешний 12-битный ШИМ (PCA9685) или ESP32.

## Telegram и время

`Telegram.WebApp.sendData()` работает с **KeyboardButton.web_app в ReplyKeyboardMarkup**. Inline-кнопка и Menu Button имеют другой механизм возврата данных и не подходят для этой схемы без сервера. Прошивка отправляет сырой JSON Bot API, получает `message.web_app_data.data` через `getUpdates` и не зависит от отсутствующих полей библиотек Telegram. При подключении удаляется прежний webhook с сохранением очереди; другой экземпляр бота одновременно запускать не следует.

Обновления запрашиваются долгим опросом: Telegram держит запрос до 10 секунд и отвечает сразу, как только появляется сообщение. Команды приходят без задержки, а запросов на порядок меньше, чем при опросе каждые 1,5 секунды. Первый запрос после загрузки выполняется без ожидания.

Обновление, которое не помещается в буферы (ответ больше 8192 байт или сообщение не влезает в JSON-документ 4096 байт — например, очень длинный текст от любого пользователя), разобрать невозможно. Прошивка берёт его `update_id` из начала ответа, пропускает такое обновление и пишет в Serial `[Telegram] Update … does not fit the buffers; skipped`. Без этого бот запрашивал бы одно и то же сообщение, пока Telegram сам не удалит его из очереди.

Документация: [Telegram Mini Apps](https://core.telegram.org/bots/webapps#keyboard-button-mini-apps), [KeyboardButton](https://core.telegram.org/bots/api#keyboardbutton), [web_app_data](https://core.telegram.org/bots/api#webappdata).

Часовой пояс: `EET-2EEST,M3.5.0/3,M10.5.0/4`, UTC+2 зимой и UTC+3 летом. Это строка `TZ_Europe_Kiev` из [ESP8266 Arduino Core 3.1.2](https://github.com/esp8266/Arduino/blob/3.1.2/cores/esp8266/TZ.h). Дополнительное ручное смещение к NTP не прибавляется. Если правила часового пояса изменятся, обновите `TIMEZONE` в `include/main.h`.

HTTPS проверяет имя сервера, срок действия и цепочку доверия. Публичные корневые сертификаты находятся в `include/telegram_ca.h`; текущая цепочка api.telegram.org проверена через OpenSSL. При смене Telegram удостоверяющего центра может потребоваться обновление корней.

## Диагностика запуска и памяти

Serial Monitor работает на 115200 бод. Сообщения `[WiFi] Connected`, `[NTP] Time ready` и `[Telegram] Ready` показывают этапы подключения. При ошибках Telegram выводятся числовые коды HTTP/транспорта/TLS и свободная память без токена бота. `[Heap] boot free=…` показывает доступную память при запуске, `largest block` — размер крупнейшего свободного блока.

HTTPS сначала согласует приёмный буфер TLS 4 КБ через MFLN и проверяет сертификаты. Если согласование не удалось, полный буфер 16 КБ используется только после проверки доступной памяти. Память JSON-ответа выделяется после TLS-handshake; полностью прочитанное HTTPS-соединение по возможности сохраняется для следующих запросов, а JSON уменьшается до фактического объёма. Постоянные сообщения хранятся во flash. При недостатке памяти запрос откладывается с сообщением `[TLS] Request postponed`, вместо заведомо рискованной попытки соединения. На реальном устройстве следует проверить стабильность свободной памяти при повторных запросах и OTA.

Чтобы проверить повторы Serial Monitor, записывайте поток непосредственно в файл:

```sh
pio device monitor -b 115200 --filter log2file
```

Нажмите Reset на плате, подождите подключения и остановите монитор через Ctrl+C. Откройте созданный `logs/device-monitor-*.log` в редакторе. Номера и время строк позволяют сравнить исходный файл с отображением терминала; каталог `logs/` исключён из Git. Повтор одного номера в скопированном выводе ещё не означает повторный вызов логирования на ESP8266.

При `JSON=NoMemory` выводится отдельная строка `[JSON]` с запрошенным размером буфера, фактической ёмкостью и использованием. Буфер ответа Telegram уменьшен до 4096 байт; тест `tests/telegram_json_test.cpp` проверяет тем же фильтром приём графика предельного размера 2048 байт и callback обновления прошивки:

```sh
c++ -std=c++11 -Iinclude -I.pio/libdeps/d1_mini/ArduinoJson/src tests/telegram_json_test.cpp -o /tmp/aquarium_telegram_json_test
/tmp/aquarium_telegram_json_test
```

## Статус процесса OTA

После нажатия «Установить прошивку» плата редактирует подпись **того же сообщения с файлом** и обновляет её по этапам:

1. Запрос принят платой, подтверждается обработка документа.
2. Получение файла из Telegram и проверка размера.
3. Скачивание и запись: показаны размер и тайм-аут (3 минуты).
4. Загрузка 100%, MD5 проверена, запись завершена.
5. Перезагрузка с ожиданием подтверждения запуска.

После перезагрузки контроллер сравнивает MD5 работающей программы с MD5 отправленного файла (а не полагается на сам факт перезапуска) и присылает новое сообщение: «✅ Прошивка обновлена» с версией, датой сборки, состоянием света и актуальной кнопкой редактора — либо «❌ Прошивка не обновилась», если суммы отличаются. Это сообщение заменяет приветствие. После его доставки сообщение с файлом прошивки и ходом установки удаляется из чата; ID этого сообщения хранится в LittleFS и переживает перезагрузку. При ручной отправке через `/update` удаляется текстовый статус бота, а отправленный вами документ остаётся. Если Telegram не разрешил удаление (сообщению больше 48 часов), ошибка остаётся только в Serial.

Во время скачивания проценты и фактическое число записанных байтов выводятся в Serial Monitor каждые 10%. Telegram получает этапы до и после скачивания: второе TLS-соединение одновременно с загрузкой не открывается. `/status` дополнительно показывает последний этап OTA. При ручной отправке документа через `/update` бот не может редактировать чужое сообщение, поэтому один раз создаёт своё текстовое сообщение и затем обновляет только его. Если плата вообще не получила нажатие (нет Wi-Fi, NTP или Telegram polling), сообщение о принятии запроса не появится; само нажатие кнопки ещё не подтверждает начало установки.

Для подтверждения после перезапуска в LittleFS перед обновлением сохраняется `/ota-result.json`. При нормальном завершении отчёт удаляется после успешной доставки; если Telegram недоступен, отправка повторяется каждые 30 секунд после восстановления Wi-Fi и NTP. Файл `/schedule.json` не изменяется. OTA теперь требует смонтированной и доступной для записи LittleFS. Ошибка создания отчёта или доставки начального статуса отменяет установку до записи программы.

Первое обновление до версии с этой функцией выполняет прежняя установленная прошивка, поэтому новые этапы появятся только при следующем OTA. Эту версию также можно один раз установить по USB.

## Восстановление после watchdog при обработке OTA-кнопки

Если контроллер непрерывно перезагружается с `Soft WDT reset`, установите актуальную прошивку по USB (`pio run -e d1_mini -t upload`); стирать flash и выполнять `uploadfs` не нужно. Сохранённый график остаётся в LittleFS.

Кнопка обновления выполняется только после успешного `answerCallbackQuery`. HTTP 400 (в том числе просроченный callback) и сетевые ошибки прекращают обработку без установки. До любых сетевых операций обработчика в LittleFS записывается `/telegram-inflight.txt` — смещение после текущего callback. При перезапуске оно используется для подтверждения сообщения в Telegram без повторения прерванного действия. После успешного подтверждения временный checkpoint удаляется; постоянного сохранения всех Telegram-сообщений нет.

Расчёт MD5 работающей программы выполняется блоками по 512 байт с передачей управления системным задачам. Между сетевыми операциями также есть паузы; HTTPS использует повторное TLS-согласование с кэшированием сессии. Watchdog не отключается. Коды API дополняются текстом ошибки без вывода URL или токена.

После восстановления дождитесь `[Telegram] Ready` и нажмите кнопку заново либо отправьте новую сборку из VS Code. Прерванный старый запрос намеренно не возобновляется автоматически.

## Приветствие после загрузки

После подключения к Wi-Fi, синхронизации времени и успешного обращения к Telegram контроллер автоматически отправляет владельцу приветствие. В сообщении — дата и время, состояние графика, основные команды и актуальная кнопка редактора. После обновления прошивки вместо приветствия приходит результат OTA (см. выше). Приветствие отправляется один раз за запуск; при ошибке доставки следующая попытка выполняется не раньше чем через 30 секунд. Простое переподключение к Wi-Fi не вызывает новое приветствие. Перед первым использованием владелец должен хотя бы один раз открыть чат бота и нажать `/start`.

## HTTPS-соединение Bot API

Запросы Telegram используют HTTP/1.1 keep-alive и одно проверенное TLS-соединение. Для последовательных этапов OTA не создаётся отдельное соединение на каждый статус. Ответ полностью читается через `HTTPClient::writeToPrint`, включая декодирование chunked-ответов, и только затем разбирается ArduinoJson. Буфер тела ограничен 8192 байтами; при превышении размера или ошибке чтения соединение закрывается. Повреждённый или не полностью прочитанный ответ не допускается к повторному использованию.

Перед скачиванием `.bin` и перед подготовкой большой клавиатуры редактора соединение API освобождается, чтобы освободить TLS-буферы. После загрузки следующие статусы снова используют одно соединение. Строка `[TLS] Opening Bot API connection for …` в Serial показывает каждое новое подключение; при обычном последовательном обмене она не должна появляться перед каждым статусом. Если сервер закрыл соединение, следующая попытка открывает новое. Проверка сертификатов и watchdog остаются включёнными.

## Смена Wi-Fi без USB

Если Wi-Fi недоступен 3 минуты подряд, контроллер поднимает открытую (без пароля) точку доступа `AquaLight-Setup`. Подключитесь к ней с телефона и откройте `http://192.168.4.1/`: страница принимает имя и пароль новой сети, сохраняет их в `/wifi.json` в LittleFS и перезагружает плату. Сохранённая сеть имеет приоритет над сетью из `secrets.h`; кнопка «Вернуть сеть из прошивки» удаляет её. Точка открытая, поэтому, пока Wi-Fi недоступен, сеть контроллера может сменить любой, кто находится рядом; прежний пароль страница не показывает, а управление светом остаётся только через Telegram.

Свет при этом продолжает работать по графику. Пока к точке доступа подключён телефон, поиск прежней сети приостановлен; точка закрывается сама, как только Wi-Fi появился. Если новые данные неверны, через 3 минуты точка доступа появится снова.


Шкала канала — текущая яркость (10 делений), `▲`/`▼` — яркость сейчас растёт или падает по графику. Ближайшая точка — это точка расписания, не обязательно изменение яркости. Без графика или LittleFS вместо шкал выводится одна строка с причиной. Перед причиной запуска ставится `⚠️`, если это watchdog или ошибка программы. «Блок» — крупнейший свободный блок RAM. Последней строкой `📦 …` добавляется этап OTA, но только когда обновление запускалось или ожидается файл.

Бот удаляет только входящее сообщение владельца с `/status`, после подтверждённой отправки ответа. Ответ со статусом и другие сообщения не удаляются. Если Telegram не разрешил удаление (например, команда уже слишком старая), ошибка фиксируется в Serial без дополнительного сообщения в чат. При неудачной отправке ответа сама команда сохраняется.

## Снижение расхода памяти при OTA

TLS-соединение явно устанавливается до отправки HTTP-запроса и проверяется результат согласования MFLN. Для `api.telegram.org` проверена поддержка фрагментов 4096 байт через OpenSSL TLS 1.2; на устройстве эта возможность проверяется заново для каждого соединения. Короткий приёмный буфер уменьшает расход RAM примерно на 12 КБ относительно 16384 байт. Если сервер не согласовал MFLN, короткое соединение закрывается до отправки запроса и выполняется проверяемая попытка с полным буфером. При недостатке памяти запрос отменяется.

Перед `Update.begin()` дополнительно проверяются свободная память и размер крупнейшего блока для буфера записи flash. Буфер скачивания в стеке уменьшен с 1024 до 256 байт. ШИМ перезаписывается только при изменении рассчитанной яркости, а не при каждой итерации загрузки.

Строки `[Memory]` показывают RAM, крупнейший свободный блок и запас стека до TLS, после согласования, перед выделением буфера Updater и во время загрузки. При запуске `[Reset]` показывает причину сброса. Эти строки вместе с исключением позволяют отличить OOM, watchdog и прочие причины; сам факт перезапуска ещё не доказывает нехватку памяти.
